# Hosting choices for the selected future site

Reviewed against official documentation on 28 September 2026. This is a proposal; no hosting account, purchase, DNS change or migration was made.

| Host | Fit for Vayam | Analytics/forms | Cost and operational consideration |
|---|---|---|---|
| Existing GitHub Pages | Keep the current temporary deployment stable while selecting a design | Static hosting; custom GA4 can run, but a real server-backed enquiry needs another service | GitHub's documented business/commercial limitations make long-term hosting suitability a decision to resolve before expanding the business site. [GitHub Pages limits](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits) |
| Cloudflare Pages | Strong candidate for the present static catalogue and a global delivery layer | Optional analytics; future form handling can use a reviewed Worker/Pages Function and storage/mail service | Static requests are free/unlimited under documented Pages pricing; dynamic Functions use Workers quotas/pricing. An apex custom domain requires Cloudflare nameservers, so mail/DNS preservation matters. [Pages pricing](https://developers.cloudflare.com/pages/functions/pricing/), [custom domains](https://developers.cloudflare.com/pages/configuration/custom-domains/) |
| Netlify | A practical alternative when integrated form handling and deployment previews matter | Native forms with spam-protection support; custom GA4 remains separate | Current credit-based plans list Free 300 credits/month, Personal $9/month and Pro starting $20/month. Form submissions are listed as free/unlimited; delivery and production deployments consume credits, so free allowance is not unlimited hosting capacity. [Netlify credit-based plans](https://docs.netlify.com/manage/accounts-and-billing/billing/billing-for-credit-based-plans/credit-based-pricing-plans/) |
| Vercel | Useful if a later selected architecture needs its framework/server features | Optional analytics and server functions; enquiry storage/mail still needs design | Hobby is restricted to non-commercial personal use. Evaluate a paid business-suitable plan rather than assuming free Hobby fits Vayam. [Vercel Hobby documentation](https://vercel.com/docs/plans/hobby) |

My current technical preference is Cloudflare Pages for a static site, conditional on an approved DNS plan and its current service terms. Netlify is the next comparison when native forms are the deciding requirement. A hosting change helps delivery and operational suitability; it does not itself create search demand or guarantee rankings. Keep GitHub as the version-control source with a reviewed release branch and rollback commit whichever host is selected.

The latest public checks already show HTTP apex, HTTP www and HTTPS www redirecting to `https://vayam-global.com/`. Preserve that one canonical identity. Do not change a working HTTPS configuration solely because an older audit described different behaviour. [GitHub's HTTPS documentation](https://docs.github.com/en/pages/getting-started-with-github-pages/securing-your-github-pages-site-with-https) explains the current hosting control.

Before any eventual cutover, export and verify the existing DNS zone, including mail MX, SPF, DKIM, DMARC, Search Console verification TXT and relevant CAA records. Build the selected site on an isolated preview, verify equivalent URLs/redirects and a reviewed privacy/analytics configuration, then prepare the exact DNS change and rollback. Account creation, service terms, paid plans, nameserver changes and the production switch are separate later decisions. Never silently migrate the business mail while moving the website.
